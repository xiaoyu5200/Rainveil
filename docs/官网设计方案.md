# Rainveil 官网 · 设计方案

- 文档编号：2026-08-24-rainveil-site-design
- 状态：草案（待审阅）
- 配套素材：`cirrus.css`（Cirrus 设计系统，用作 token 来源）

---

## 1. 项目概览

为 Minecraft 服务器「Rainveil · 雨幕」建立官方网站。

| 项 | 值 |
| --- | --- |
| 服务器名称 | Rainveil · 雨幕 |
| 游戏版本 | Java 1.21.11（生存服） |
| 服务器类型 | 生存 RPG |
| 服务器地址 | mc.xiaoyu.wiki |

站点目标：让玩家快速了解服务器、查看玩法与规则、上手进入游戏、了解赞助方案，并与社区建立联系。

---

## 2. 已确认的决策

| 维度 | 决策 |
| --- | --- |
| 设计方向 | Cirrus 亮色风（克制的云计算风，非像素风） |
| 站点结构 | 多页站 |
| 页面范围 | 首页 / 玩法详解 / 开始游玩 + 规则 / 商店与赞助 |
| 技术栈 | React + Vite + TypeScript |
| 样式层 | Tailwind CSS（把 Cirrus token 映射为 Tailwind 主题色板） |
| 路由 | react-router，真实 URL |
| 动态内容 | 纯静态内容（无后端、无数据库） |
| MC 风味 | 纯 Cirrus 亮色，不引入像素方块装饰 |

## 3. 设计系统（Tailwind token 映射）

将 `cirrus.css` 的 token 值迁入 `tailwind.config.ts` 的 `theme`：

### 3.1 颜色

| Tailwind token | 值 | 用途 |
| --- | --- | --- |
| `ink` | `#0e1116` | 主文字、主填充 |
| `cloud` | `#ffffff` | 表面、卡片 |
| `mist` | `#5b6472` | 次要文字 |
| `mist-soft` | `#8a93a3` | 弱文字/占位 |
| `edge` | `#e3e8ee` | 边框 |
| `signal` | `#2e7def` | 聚焦、链接、强调蓝 |
| `citrus` | `#ff7a3d` | 点缀橙 |
| `meadow` | `#2bc48a` | 成功、在线绿 |
| `sky` | `#edf2f7` | 页面背景（云宫色） |

语义别名（在 `theme.extend.colors` 中再映射一层）：
`page: sky`、`strong: ink`、`muted: mist`、`soft: mist-soft`。

### 3.2 其它

- 边框圆角：`pill = 999px`、`input = 999px`、`check = 8px`（映射为 Tailwind 的 `rounded-full`、自定 `rounded-pill`）。
- 字体：`sans = "Inter", system-ui, ...`。
- 阴影：Cirrus 的两层柔和阴影（`shadow-whisper` 低、`shadow-float` 中）。
- 动效：`--ease-soft = cubic-bezier(0.22, 1, 0.36, 1)`，时值 `220ms`。
- 聚焦环：`0 0 0 3px rgba(46,125,239,0.28)`。

### 3.3 设计原则

- 全站胶囊几何，拒绝直角暴力。
- hairline 边框（`1px solid edge`）做分隔，而非重阴影。
- 每个 hero 仅使用一次斜体衬线（Instrument Serif）点缀。
- 留白大、层级克制，仅两级透明度阴影。
- 通过 CSS 变量 / Tailwind 主题实现明暗切换预留（本期只做亮色）。

### 3.4 文案规则（全站强制）

1. **全站禁止使用 emoji**（含标题、正文、按钮、标签、提示、公告文案）。统一用文字 + SVG 图标表达，不用 emoji 充当图标或装饰。
2. 文案用中文为主，保持简洁、克制；专有名词（IP 地址、版本号、服务器/游戏术语）按原样保留英文或数字。
3. 强调用字重、斜体衬线点缀或颜色（`signal` / `citrus` / `meadow`），不使用表情符号。
4. 若 icon 组件需符号类视觉，一律使用项目内统一 SVG 图标，不引用 emoji 字体。

## 4. 信息架构与路由

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `/` | 首页 | 品牌入口、概览、卖点、公告、CTA |
| `/modes` | 玩法详解 | 生存 RPG 玩法 / 特色系统详情 |
| `/guide` | 开始游玩 + 规则 | 进服步骤、服务器规则、FAQ |
| `/store` | 商店 / 赞助 | 付费权益、赞助方案 |
| `*` | 404 | 未匹配页面 |

所有页面共用同一套布局：顶部导航（胶囊悬浮）+ 底部 Footer。

---

## 5. 页面板块设计

### 5.1 首页（`/`）

- Hero：标题 + 斜体强调词 + 一次性简介 + IP 复制按钮 + 「加入服务器」主 CTA。
- 服务器概览条：版本徽章、IP、类型（生存 RPG）、在线人数（静态占位）。
- 卖点区：3–4 个核心卖点（HaaS 式卡片网格）。
- 玩法速览：指向 `/modes` 的前往卡片。
- 最新公告：静态列表区段。
- 底部 CTA：再次引导进服。

### 5.2 玩法详解（`/modes`）

- 玩法总览说明。
- 玩法/特色系统卡片列表，每项含名称、简介、关键特性，支持逐个展开。
- 内容项来源：`src/content/modes.ts`。

### 5.3 开始游玩 + 规则（`/guide`）

- 进服步骤：版本选择、地址、白名单 / 验证。
- 服务器规则列表（分块：通用、游戏、聊天、违规处罚）。
- FAQ 折叠面板。

### 5.4 商店 / 赞助（`/store`）

- 付费项目 / 赞助方案列表（等级、权益、定价）。
- 权益对照表。
- 购买 / 赞助指引（QQ / 平台 / 客服）。

## 6. 组件设计

遵循「单一职责、清晰接口、可独立理解与测试」。

### 6.1 布局组件

| 组件 | 职责 | 依赖 |
| --- | --- | --- |
| `AppLayout` | 包 NavBar + Outlet + Footer | react-router `Outlet` |
| `NavBar` | 胶囊导航、当前项高亮、移动端收合 | useLocation |
| `Footer` | 底部信息、社交链接、版权 | content.site |

### 6.2 通用 UI 组件

| 组件 | 职责 |
| --- | --- |
| `Container` | 页宽约束与内边距 |
| `Section` | 分节容器 + 标题、副标题 |
| `Card` | 表面卡片（cloud 底 + hairline 边框） |
| `PillButton` | 胶囊按钮（主 / 次 / 幽灵三态） |
| `Badge` | 小胶囊标签（版本、类型） |
| `StatTile` | 概览统计块（版本/IP/类型/在线） |
| `CopyIp` | 复制 IP 的交互按钮 |
| `Accordion` | 折叠面板（FAQ、规则分组） |
| `Icon` | 统一 SVG 图标封装 |

### 6.3 页面组件

- `HomePage`、`ModesPage`、`GuidePage`、`StorePage`、`NotFoundPage`：每个页面从 `src/content/*` 读取数据渲染，不直接内联内容。

---

## 7. 数据与内容

纯静态内容，全部以类型化数据文件存放，集中在 `src/content/`：

| 文件 | 内容 |
| --- | --- |
| `site.ts` | 名称、版本、类型、IP、简介、社区联系 |
| `modes.ts` | 玩法 / 特色系统数组 |
| `rules.ts` | 规则分组数组 |
| `store.ts` | 赞助方案 / 权益数组 |
| `announcements.ts` | 公告数组 |

每个导出带 `TypeScript` 类型，组件只依赖类型与字段，不硬编码文本。未来接后端时，仅替换数据来源即可，组件层不变。

---

## 8. 视觉与响应式

- 背景：`sky`（云宫色）全局。
- 桌面：多列网格；移动端：单列堆叠，导航收合为菜单。
- 可访问性：
  - 统一 `focus-visible` 聚焦环。
  - 语义标签（`nav`、`main`、`footer`、`article`）。
  - 色彩对比满足 WCAG AA。
- 首屏性能：路由级代码分割，图片懒加载。

## 10. 实施阶段（概要）

1. 脚手架：Vite + React + TS + Tailwind + react-router；接入 Cirrus 基座。
2. Tailwind 主题：映射 3.1 / 3.2 的全部 token。
3. 布局：AppLayout / NavBar / Footer。
4. 通用 UI 组件。
5. 逐页实现：Home → Guide → Store → Modes → 404。
6. 内容填充：补齐 `src/content/*`。
7. 响应式 + 可访问性 + 构建验证（`vite build` 通过）。
8. 交付自检。

详细的每步任务与验收，在实现计划（writing-plans）中展开。
